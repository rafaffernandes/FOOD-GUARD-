Food Guard · Runbook

Guia de Validação e Go-Live — passo a passo

Tudo que você precisa fazer pra validar a Food Guard nos previews e, só depois, publicar em produção. Por plataforma, com links e o que conferir em cada etapa.

Antes de começar — 3 coisas:
  1. Nada está em produção. Tudo vive no PR #1 e nos previews. Só vai pro ar quando você validar e me disser "pode publicar".
  2. Onde colar as chaves: Vercel → projeto food-guard-cnhl → Settings → Environment Variables. Marque "All Environments" (assim o preview também funciona pra testar). Abrir env vars
  3. Onde testar: o preview do PR → food-guard-cnhl-git-claude-charm…vercel.app. Após colar env vars, dê Redeploy no preview pra ele recarregar.
Faça na ordem (cada bloco depende do anterior). Tempo total: ~1–2h.

1 Banco de dados — Supabase obrigatório

É onde ficam leads, pagamentos e os rascunhos dos agentes.

  1. Acesse app.supabase.com → crie um projeto (região South America / São Paulo).
  2. Menu SQL Editor → cole e rode, um de cada vez, o conteúdo destes 3 arquivos do repositório:
    • supabase/schema.sql (leads + consentimento)
    • supabase/fase-3-agents.sql (prospects, rascunhos, atividade)
    • supabase/payments.sql (pagamentos)
  3. Menu Project Settings → API → copie a Project URL e a chave service_role (secreta).
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOi...
✅ Validar: em Table Editor, devem aparecer as tabelas leads, prospects, outreach_drafts, content_drafts, lead_activity e payments.

2 E-mail — Resend obrigatório

Envia o relatório do diagnóstico (PDF) e os alertas internos da equipe.

  1. resend.com/api-keys → criar API key (começa com re_).
  2. resend.com/domains → adicionar foodguard.com.br → colar os registros SPF/DKIM no DNS do domínio → aguardar "Verified". Sem isso o e-mail cai em spam.
RESEND_API_KEY=re_xxxxxxxx RESEND_FROM="Food Guard <diagnostico@foodguard.com.br>" TEAM_NOTIFY_EMAIL=seu-email@foodguard.com.br
✅ Validar: no preview, faça um diagnóstico de teste com seu próprio e-mail → o relatório deve chegar na sua caixa em 1–2 min.

3 Pagamento — Asaas conta já criada

Cobrança dos planos + confirmação automática (webhook) + onboarding.

  1. No Asaas (faça primeiro no sandbox, depois repita na produção): Integrações → Webhooks → URL:
    https://foodguard.com.br/api/webhooks/asaas (no teste, use a URL do preview + /api/webhooks/asaas)
    → defina um token e cole nos dois lados.
  2. Nos links de pagamento dos 3 planos (Básico R$1.200 · Essencial R$2.200 · Premium R$3.200), configure o redirecionamento de sucesso para /obrigado.
  3. Cole as chaves (use as do sandbox pra testar):
ASAAS_API_KEY=$aact_xxxx ASAAS_ENV=sandbox # depois "production" ASAAS_WEBHOOK_TOKEN=um-token-secreto-forte
✅ Validar (sandbox): faça um pagamento de teste → (1) aparece uma linha na tabela payments do Supabase; (2) chega um e-mail "💰 Pagamento confirmado"; (3) o navegador cai na página /obrigado.

4 IA dos agentes — Claude API obrigatório p/ agentes

Sem a chave, os agentes funcionam em modo "rascunho determinístico" (texto fixo). Com ela, personalizam dentro das regras.

  1. console.anthropic.com (ou platform.claude.com) → API Keys → criar chave.
ANTHROPIC_API_KEY=sk-ant-xxxx AGENTS_MODE=simulacao # mantenha em simulacao (não envia nada) AGENTS_KILL_SWITCH=off # "on" desliga todos os agentes na hora
✅ Validar: abra no preview /api/agents/teste-prospeccao (se setou CRON_SECRET, precisa do header Authorization: Bearer SEU_SEGREDO) → deve retornar os 11 cenários com os textos da prospecção.

5 Painel de aprovação obrigatório

Onde você revisa e aprova os rascunhos dos agentes. Protegido por senha.

ADMIN_USER=voce ADMIN_PASSWORD=uma-senha-forte CRON_SECRET=outro-segredo-forte # protege as rotas automáticas dos agentes
✅ Validar: abra /admin/aprovacoes no preview → o navegador pede usuário/senha (Basic Auth) → após logar, vê a fila (vazia por enquanto, normal).

6 Medição — GA4 + Meta Pixel pré-requisito do Google Ads

Sem isso, o tráfego pago roda cego (não dá pra otimizar por conversão).

  1. analytics.google.com → criar propriedade → copiar Measurement ID (G-XXXX).
  2. Gerenciador de Eventos da Meta → criar Pixel → copiar o ID.
NEXT_PUBLIC_GA_ID=G-XXXXXXX NEXT_PUBLIC_META_PIXEL_ID=000000000000000
✅ Validar: no GA4 → relatório Tempo real → abra o preview noutra aba → sua visita deve aparecer.

7 Marca e dados legais obrigatório p/ LGPD

NEXT_PUBLIC_SITE_URL=https://foodguard.com.br NEXT_PUBLIC_WHATSAPP=5511XXXXXXXXX # nº oficial, só dígitos NEXT_PUBLIC_CONTACT_EMAIL=contato@foodguard.com.br NEXT_PUBLIC_LEGAL_NAME="Food Guard ..." # razão social NEXT_PUBLIC_CNPJ=00.000.000/0001-00
✅ Validar: no rodapé do preview aparece o CNPJ + razão social e os links Política de Privacidade e Termos abrem (/privacidade, /termos). Confira também que o botão flutuante e o "Fui autuado" abrem o WhatsApp certo.

8 Presença externa (sem código) recomendado

  1. Google Business Profile: business.google.com → criar perfil da Food Guard (nome, telefone, área de SP). É o canal orgânico local nº 1 e ajuda as LLMs a te recomendarem.
  2. Prova social: me envie 1 depoimento de cliente + 2–3 fotos reais (Renan em visita / cozinha) → eu coloco no site (hoje ele é 100% sem foto).

10 Go-Live (publicar em produção)

Só depois de validar tudo acima. Quando estiver ok:
  1. Confirme que as env vars estão também em Production (não só Preview).
  2. Vire o Asaas para ASAAS_ENV=production e configure o webhook de produção.
  3. Me diga "pode publicar" → eu faço o merge do PR #1 → a Vercel publica em foodguard.com.br em 1–2 min.
Os agentes continuam em simulação (AGENTS_MODE=simulacao) mesmo em produção, até você validar os rascunhos e mandar ligar o envio real (que ainda depende da WhatsApp Cloud API + pipeline de empresas).
