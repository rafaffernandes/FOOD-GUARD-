1 Criar o registro DKIM · Registro.br · ~10 min

🔍 O que eu descobri: os outros dois registros do mesmo lote já publicaram há tempos, mas o resend._domainkey retorna "esse nome não existe". Ou seja: não é demora de propagação — ele não chegou a ser salvo. A causa mais provável é o tamanho: o valor DKIM tem cerca de 400 caracteres, e um registro TXT só aceita blocos de 255. O Registro.br costuma recusar, às vezes sem avisar direito.
  1. No Resend → Domains → clique no domínio → seção DKIM. Passe o mouse sobre o valor e use o ícone de copiar (nunca selecione com o mouse — o texto na tela vem cortado).
  2. No Registro.br → seu domínio → Configurar zona DNS → + Nova entrada.
  3. Preencha: Nome = resend._domainkey · Tipo = TXT · Dados = o valor copiado.
  4. Se der erro ou não salvar (é o esperado, pelo tamanho): quebre o valor em duas partes entre aspas, sem espaço nem quebra de linha dentro de cada aspas:
    "p=MIGfMA...primeira_metade" "segunda_metade...IDAQAB"
    Isso é o jeito padrão de registrar um TXT longo, e o Resend lê normalmente.
  5. Salve → volte no Resend → "I've added the records".
  6. Me peça "verifica o DNS" — eu consulto daqui em segundos e confirmo se publicou, sem você precisar ficar recarregando a página.

2 Tirar o Asaas do sandbox · o mais importante

💸 O que o seu link revelou: ele começa com sandbox.asaas.com — ambiente de simulação. Em produção começaria com www.asaas.com. A integração funciona (isso é ótimo), mas está apontando para o lugar errado.

Por que: li o código (lib/integrations/asaas.ts) e ele usa primeiro um link fixo, se existir; só depois chama a API. Então há duas causas possíveis — cheque na ordem:

  1. Causa mais provável — links fixos de sandbox. Na Vercel → Environment Variables → busque por ASAAS_PAYMENT_LINK. Se aparecerem _BASICO, _ESSENCIAL, _PREMIUM, abra cada uma (⋯ → Edit) e veja se o valor contém a palavra sandbox.
    Se contiver, escolha um caminho:
      • Simples: apague as três (⋯ → Delete). Sem elas, o site cria a cobrança pela API automaticamente, já em produção.
      • Controlado: crie 3 links novos em www.asaas.com → Vendas → Link de pagamento (Básico R$ 1.200 · Essencial R$ 2.200 · Premium R$ 3.200, assinatura mensal) e substitua os valores.
  2. Confira o ambiente. ASAAS_ENV tem que ser exatamente production — tudo minúsculo, sem espaço antes ou depois.
  3. Confira a chave. ASAAS_API_KEY tem que ser a de produção. A de produção começa com $aact_prod_; se começar diferente, ainda é a de sandbox — pegue a certa em www.asaas.com → ícone de perfil → Integrações → Chave de API.

3 Cadastrar o webhook do Asaas · ~5 min

É o aviso automático que o Asaas manda pro site quando alguém paga. Sem ele o pagamento acontece, mas você não é avisado e nada fica registrado no banco. Você ainda não me confirmou se fez essa parte — se já fez, é só conferir os campos.

  1. Em www.asaas.com → ícone de perfil → Integrações → aba Webhooks → Adicionar webhook.
  2. URL: https://food-guard-cnhl.vercel.app/api/webhooks/asaas
  3. Token de autenticação: invente uma senha forte e guarde. Versão da API: v3. Status: Ativo.
  4. Eventos: marque os de Cobrança — no mínimo PAYMENT_CONFIRMED, PAYMENT_RECEIVED, PAYMENT_OVERDUE, PAYMENT_REFUNDED, PAYMENT_CHARGEBACK_REQUESTED. Pode marcar todos os de cobrança — os extras são ignorados sem erro.
  5. Na Vercel: ASAAS_WEBHOOK_TOKEN = exatamente o token do passo 3 (Sensitive ligado). Se os dois não forem idênticos, o site recusa o aviso. (Confirmei no código: o Asaas envia no cabeçalho asaas-access-token e o site compara.)
