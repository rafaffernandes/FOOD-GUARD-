Como pôr Supabase, Resend e Asaas em PRODUÇÃO

As contas já existem e funcionam em teste. Este guia mostra onde entrar, o que clicar e o que copiar/colar, tela por tela. Tudo abaixo foi conferido no código do site (nomes de variáveis, header do webhook, ordem do checkout). Tempo total: ~45–60 min.

⚠️ Antes de tudo — o projeto certo na Vercel. O repositório está conectado a 5 projetos na Vercel (cnhl, spil, geuo, pg2k, rafaelfernandesfoodguard). O site oficial é o food-guard-cnhl (https://food-guard-cnhl.vercel.app). Toda variável deste guia vai NESSE projeto. Se colocar em outro, nada funciona. (Depois, se quiser, dá pra apagar os 4 duplicados em Settings → Advanced → Delete Project — opcional.)

0 Como se adiciona variável na Vercel · você vai repetir isso várias vezes

O que é "variável de ambiente"? É um cofrinho de configurações que o site lê quando liga: as senhas das integrações (Supabase, Resend, Asaas) ficam guardadas ali, fora do código. Você vai criar uma por uma nesse cofrinho.

🌎 O painel da Vercel é só em inglês — não tem como mudar pra português. Duas saídas: (a) use a tabelinha de tradução abaixo (tudo que aparece na tela está nela); (b) no Chrome, clique com o botão direito em qualquer parte da página → "Traduzir para o português" — o painel inteiro fica em pt-BR (os passos continuam valendo; só os nomes ficam traduzidos).

  1. Abra vercel.com → canto superior direito, botão Log In (Entrar) → Continue with GitHub (Continuar com GitHub) → autorize se pedir.
  2. Você cai numa tela com cards dos projetos (retângulos com os nomes). Ache o card food-guard-cnhl e clique no nome dele. ⚠️ Tem 5 parecidos — é o cnhl.
  3. Abriu a página do projeto. No topo tem um menu horizontal: Overview · Deployments · Analytics · … · Settings. Clique em Settings (Configurações — é o último, à direita).
  4. Apareceu uma lista no lado esquerdo (General, Domains, …). Clique em Environment Variables (Variáveis de ambiente — 3º item, aproximadamente).
  5. No alto da tela tem um formulário de criar variável com dois campos lado a lado:
    • Key (Nome): digite o nome EXATAMENTE como está neste guia — maiúsculas, com underline _, sem espaço. Ex.: ASAAS_ENV
    • Value (Valor): cole o valor (a chave que você copiou, ou o texto indicado). Sem espaço sobrando no começo/fim.
  6. Logo abaixo, em Environments, há 3 caixinhas: Production, Preview, Development. Deixe pelo menos Production e Preview marcadas (se as 3 já vierem marcadas, pode deixar assim).
  7. Se a variável for senha/chave (tudo que este guia marcar como Sensitive): ligue a chavinha Sensitive (fica preta/azul quando ligada). Depois de salvar, nem você vê mais o valor — se errar, é só substituir.
  8. Clique no botão preto Save (Salvar). A variável aparece na lista abaixo do formulário. Repita os passos 5–8 pra cada variável do guia.
  9. Errou algo? Na lista, ache a variável → botão ⋯ no fim da linha → Edit (Editar) → corrija → Save.
  10. No final de TUDO (etapas 1–4 do guia concluídas): menu do topo → Deployments (Publicações) → a primeira linha da lista (a mais recente) → botão ⋯ bem à direita da linha → Redeploy (Republicar) → na janelinha que abre, confirme clicando em Redeploy de novo → aguarde ~2 min até o status Ready (bolinha verde). Variável nova só passa a valer depois desse Redeploy.

1 Supabase → produção · ~10 min

O código usa NEXT_PUBLIC_SUPABASE_URL + SUPABASE_SERVICE_ROLE_KEY (verificado em lib/integrations/supabase.ts). Supabase não tem "modo teste/produção" — o mesmo projeto serve, só precisamos garantir as tabelas e as chaves na Vercel.

  1. Acesse supabase.com/dashboard → entre → clique no seu projeto.
  2. Conferir as tabelas: menu lateral esquerdo → Table Editor (ícone de tabela) → schema public. Você deve ver: leads, consent_log e payments.
  3. Se faltar alguma: menu lateral → SQL Editor → botão + New query. Em outra aba, abra o GitHub: github.com/rafaffernandes/FOOD-GUARD- → pasta supabase → abra schema.sql → botão Copy raw file (ícone de cópia) → cole no SQL Editor → botão Run (ou Ctrl+Enter) → deve aparecer "Success".
  4. Repita o passo 3 para payments.sql e fase-3-agents.sql (nessa ordem).
  5. Pegar as chaves: menu lateral, lá embaixo → Project Settings (engrenagem) → API (em algumas contas aparece como API Keys / Data API).
  6. Copie o Project URL (formato https://xxxxx.supabase.co) → na Vercel crie NEXT_PUBLIC_SUPABASE_URL com esse valor.
  7. Na mesma tela, ache a chave service_role (seção "Project API keys"; clique em Reveal/olhinho para mostrar) → copie → na Vercel crie SUPABASE_SERVICE_ROLE_KEY com Sensitive ativado.
🔒 Cuidado: existem 2 chaves ali — anon (public) e service_role (secret). O site usa a service_role. Ela dá acesso total ao banco: nunca cole em outro lugar além da Vercel.

2 Resend → produção · ~15 min + espera de DNS

Em teste o Resend usa onboarding@resend.dev, que só entrega no SEU próprio e-mail. Produção = domínio verificado + remetente próprio (verificado em lib/integrations/resend.ts).

  1. Acesse resend.com → Sign in → menu lateral esquerdo → Domains.
  2. Se foodguard.com.br já aparecer com selo verde Verified, pule para o passo 6.
  3. Senão: botão Add Domain → digite foodguard.com.br → Add. O Resend mostra uma lista de registros DNS (1 MX, 1 TXT/SPF e 1 TXT/DKIM tipo resend._domainkey). Deixe essa aba aberta.
  4. Em outra aba, entre no site onde o domínio foi registrado (ex.: Registro.br → "Meus domínios" → foodguard.com.br → Editar zona DNS). Para cada registro do Resend: Nova entrada → copie exatamente Tipo, Nome/Host e Valor → salve.
  5. Volte ao Resend → botão Verify DNS Records. A verificação leva de minutos a ~1h. Status final: Verified (verde). (Pode seguir as etapas 3 e 4 enquanto espera.)
  6. Chave de produção: menu lateral → API Keys → Create API Key → Name: food-guard-producao → Permission: Sending access → Create → copie o valor re_... agora (só aparece uma vez) → na Vercel: RESEND_API_KEY (Sensitive).
  7. Na Vercel, crie RESEND_FROM com o valor exato: Food Guard <diagnostico@foodguard.com.br> (com o < >). Não precisa criar caixa de e-mail — com o domínio verificado, qualquer endereço @foodguard.com.br envia.
  8. Opcional: TEAM_NOTIFY_EMAIL = seu Gmail — é onde chegam os avisos internos ("💰 pagamento confirmado", lead quente). Sem ela, o código usa o NEXT_PUBLIC_CONTACT_EMAIL.

3 Asaas → produção · ~20 min · a parte mais importante

Sandbox e produção são dois ambientes separados: sandbox.asaas.com (teste, onde está hoje) e www.asaas.com (dinheiro real). Verificado no código: com ASAAS_ENV=production o site passa a chamar api.asaas.com.

  1. Acesse www.asaas.com → Entrar → conta real (não a sandbox).
  2. Conta aprovada? Se o painel ainda pedir "verificação de conta"/envio de documentos (CNPJ, sócio, selfie), complete primeiro — sem aprovação a conta não gera cobranças reais. (Se já usa o Asaas normalmente, já está ok.)
  3. Chave de API de produção: clique no ícone do seu perfil (canto superior direito) → Integrações → aba Chave de API (caminho alternativo: Configurações → Integrações) → Gerar nova chave → dê o nome food-guard-site → copie na hora (só aparece 1 vez; começa com $aact_prod_).
  4. Na Vercel: edite a variável ASAAS_API_KEY (troque a chave sandbox pela de produção; Sensitive) e edite/crie ASAAS_ENV = production (minúsculo, exatamente assim).
  5. Webhook (confirmação de pagamento): no mesmo menu Integrações → aba Webhooks → Adicionar webhook. Preencha:
    • Nome: Food Guard site
    • URL: https://food-guard-cnhl.vercel.app/api/webhooks/asaas
    • E-mail: o seu (avisos de falha)
    • Versão da API: v3
    • Token de autenticação: invente uma senha forte (ex.: 30 caracteres aleatórios) e guarde
    • Fila de sincronização: sequencial (padrão) · Status: Ativo
    • Eventos: marque os de Cobranças — no mínimo PAYMENT_CONFIRMED, PAYMENT_RECEIVED, PAYMENT_OVERDUE, PAYMENT_REFUNDED, PAYMENT_CHARGEBACK_REQUESTED (pode marcar todos de cobrança; os extras são ignorados sem erro) → Salvar.
  6. Na Vercel: ASAAS_WEBHOOK_TOKEN = exatamente o token que você digitou no passo 5 (Sensitive). O Asaas manda esse token no header asaas-access-token e o site confere — verificado no código do webhook.
  7. Opcional (recomendado) — links de pagamento fixos: no painel → Vendas → Link de pagamento → Criar link. Crie 3 (assinatura mensal recorrente): Básico R$ 1.200 · Essencial R$ 2.200 · Premium R$ 3.200. Copie as 3 URLs e crie na Vercel: ASAAS_PAYMENT_LINK_BASICO, ASAAS_PAYMENT_LINK_ESSENCIAL, ASAAS_PAYMENT_LINK_PREMIUM. Verificado: o site usa esses links antes de tentar a API — você fica no controle do texto/valor pelo painel.

4 Dados do site · ~5 min

  1. NEXT_PUBLIC_SITE_URL = https://food-guard-cnhl.vercel.app (sem barra no final; se ativar domínio próprio depois, troque aqui).
  2. NEXT_PUBLIC_WHATSAPP = 5511976466553 — só dígitos, formato 55+DDD+número. (Esse já é o padrão no código; crie a variável só se o número for outro.)
  3. NEXT_PUBLIC_CONTACT_EMAIL = contato@foodguard.com.br (padrão do código; crie só se for outro).
  4. Opcional (tráfego pago depois): NEXT_PUBLIC_GA_ID (Google Analytics, formato G-XXXX) e NEXT_PUBLIC_META_PIXEL_ID.
ℹ️ Não configure ANTHROPIC_API_KEY, AGENTS_MODE, AGENTS_KILL_SWITCH ou CRON_SECRET — são dos agentes autônomos, que ficam em standby (v2). Se AGENTS_MODE já existir, deixe com o valor simulacao.

5 Redeploy + teste real · ~10 min

  1. Redeploy: Vercel → food-guard-cnhl → Deployments → primeiro da lista → ⋯ → Redeploy → confirme e espere ficar Ready.
  2. Teste do lead: abra o site em aba anônima → faça o diagnóstico completo usando seu e-mail real → confira: (a) no Supabase, Table Editor → leads tem uma linha nova; (b) o e-mail com o relatório chegou (olhe o spam na 1ª vez).
  3. Teste do checkout: vá em /planos → clique em contratar → a página do Asaas deve abrir com o plano e o valor certos. (Agora é dinheiro real — não precisa pagar pra validar a tela.)
  4. Teste completo do pagamento (opcional): pague o menor valor via PIX → confira no Supabase a linha em payments + o e-mail "💰 Pagamento confirmado" → depois estorne no painel Asaas (abrir a cobrança → Estornar).
  5. Me avise aqui no chat. Eu rodo o QA gate (nota ≥90) e, com o seu "pode publicar", subo tudo pra produção na main.
